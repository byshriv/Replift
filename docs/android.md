# Android wrapper and distribution

Phase 6 uses Capacitor 8 to package the existing React build. This is a feasibility build for review; physical-device acceptance is still required. No remote website is loaded as the app, no backend is added, and existing IndexedDB/schema/sync/backup code is reused. App ID is permanently `io.github.byshriv.replift`. Keep the local origin `https://localhost` unchanged across updates: changing it can strand WebView data. Current minimum SDK is 24, target/compile SDK 36, Java 21. Production and the original deployment are unchanged.

## Build

Install Node 24, Java 21 and Android SDK platform 36/build tools. Set `JAVA_HOME` and `ANDROID_HOME` to their installation folders. Run `npm ci`, then `npm run android:prepare`. This builds the web app and runs `cap sync android`; do this after every web/plugin change. Generated web copies, local SDK paths and build output are ignored. Capacitor configuration deliberately has no `server.url`, remote live updates, cleartext allowance or native HTTP interception. Release WebView debugging is disabled.

For an unsigned review build on macOS/Linux, run `cd android` then `./gradlew assembleRelease lintRelease`; on Windows use `gradlew.bat`. CI performs that build without any signing secrets. Its unsigned artifact cannot be installed as a release APK until signed. For a debug build use `assembleDebug`. Never use debug signing for direct distribution.

For signed builds, create and retain an RSA release key outside this repository. The owner authorized a new identity because no earlier key exists. Never replace that identity for updates. An external, access-restricted JSON file contains `keystore` (absolute path), `alias`, `storePassword` and `keyPassword`. Set `REPLIFT_SIGNING_CONFIG` to that file, `REPLIFT_VERSION_CODE` to a positive integer greater than every distributed version, and optionally `REPLIFT_VERSION_NAME`. Run `npm run android:release`. The script checks that config and key resolve outside the repo, passes credentials only through child environment variables, then copies the signed APK and SHA-256 file to ignored `artifacts/`. It never creates or uploads keys. Do not enable shell tracing or Gradle debug logs around credentials.

Verify the APK with Android build-tools `apksigner verify --verbose --print-certs <apk>` and inspect the package/version with `aapt dump badging <apk>`. Record the certificate digest alongside each distribution. APK signing proves publisher identity and package integrity, not app behavior or data safety. A second build with an increased version code and identical signer is prepared for the upgrade drill; signature verification alone does not establish that installation preserves data.

Back up the keystore AND its credentials to two encrypted, owner-controlled locations outside the checkout, with at least one offline copy. Test that a backup key can sign an increased-version disposable build and compare its certificate before relying on it. Files merely retained on this computer are not an independently verified backup. Losing the key prevents in-place upgrades; uninstalling to work around a different signer destroys local app data. Never put this JSON/key in GitHub repository secrets, fixtures, source archives, screenshots or issues as part of this phase.

## Dropbox console and return

1. Open the existing app in the [Dropbox App Console](https://www.dropbox.com/developers/apps).
2. In Settings, add the exact OAuth 2 redirect `io.github.byshriv.replift://oauth/dropbox`. Keep existing web redirects. Do not change app-folder access or production configuration to make a test pass.
3. Confirm public-client PKCE access and the existing content read/write, metadata read and account-info read scopes. This is a public app key; no app secret belongs in the APK.
4. Install the review APK with disposable data and tap Settings → Connect Dropbox. Authorization opens an Android browser Custom Tab outside the app WebView. Returning opens Settings with an account/content preview. Only the explicit account approval connects and merges it.
5. Test cancellation, wrong/expired state, browser dismissal, browser Back and process death while the browser is open. Both the `appUrlOpen` event and `getLaunchUrl` cold-start path are handled. The PKCE verifier/state/redirect/ten-minute expiry live in the existing private IndexedDB store. The pending state is single-use; duplicate warm/cold delivery is serialized. Stale launch intents without a pending attempt are ignored. Unrelated/malformed URLs do not navigate or consume authorization.

Custom schemes can be claimed by other Android apps. PKCE protects an intercepted authorization code; an intercepted return can still disrupt sign-in. No domain/App Links/backend architecture is introduced. Live provider/console acceptance is unverified until the owner performs the drill; do not claim successful authorization from the fake-provider tests.

## Native behavior and data transfer

Back closes the top dialog, then returns to Home, then requires a second press within two seconds to exit. Failed/pending saves or unavailable storage block explicit exit and show a warning. Saved workout drafts remain in the existing transactional store. OS process termination is outside the Back handler and still requires device interruption checks. Set completion requests light haptics only on Android when the existing `st.vib` preference is enabled. Unsupported actuators do not block saving.

Cards use the native chooser with PNG files. Complete backups use the same chooser with JSON, including original photos and retained conflicts, excluding connection credentials. Choosing a recipient is not proof that it saved a durable copy; the UI tells the user to check. Cancelling never starts a hidden browser download or marks a backup as downloaded. FileProvider exposes only `cache/replift-share/`, with temporary read grants. Share copies remain in app cache for recipients and are removed after a day on the next share, or by Android cache eviction. This cleanup never touches the database, originals or user-chosen destination files. No broad external-storage permission is requested. Automatic OS backup/device transfer is disabled so private connection credentials are not silently copied.

PWA/browser and APK storage are separate, even on the same phone. Never uninstall, clear either copy, or promise automatic migration. Use one of these explicit paths:

1. In the source app, wait for “Saved on this device”. Export/share a complete backup and save it outside Replift. Open the saved file to confirm it exists; preserve both copies if the destination already has edits.
2. In destination Settings → Dropbox and recovery → Preview a backup to restore, choose that JSON. Read the before/after counts. **Restore with recovery point** explicitly replaces destination content, first atomically saving its previous content for recovery. It does not clear the source. Re-export and compare history, programs, measures, original photos and drafts. The current import limit is 32 MiB; oversized files are refused without deleting them. Large-data handling remains a release gate.
3. Alternatively, connect both apps to the same optional Dropbox account, approve the account preview, sync and review conflicts. Wait for acknowledgements and verify content on both; never use whole-copy overwrite to conceal a sync failure. This path requires separate live testing. Credentials remain independently authorized on each installation.

## Install, update and physical-device acceptance

Direct APK distribution can use a GitHub Release with source, APK, checksums and known limitations after release authorization. This phase opens a review PR only; it does not publish a release or alter production. There is no paid store/backend requirement.

1. Save a complete external backup first. Download the review APK from a trusted owner-provided location and compare SHA-256 and signer. Android: open the APK in Files → Settings when prompted → allow installs from that source → return → Install. Disable that source permission afterward if desired.
2. Open once; check app identity/icon/dark launch, navigation, keyboard/insets/rotation, text scaling, file picker and TalkBack. Create synthetic history, an unfinished draft, a routine edit, measure and original photo. Reopen offline and compare every item.
3. Enable USB debugging only for an intentional test. `adb install <version-1.apk>` installs fresh; **never run uninstall or clear** to get a test passing. Install the higher-version same-key APK using Files → Update, or `adb install -r <version-2.apk>`. Confirm the same app is updated, then cold-launch offline and verify all seeded content, IDs, draft fields, pending sync work and original photo bytes. Record device/Android/WebView versions and both APK hashes/signers. Test a rejected wrong-key update only on a disposable installation; never uninstall afterward as a workaround.
4. Run the live OAuth drill above, including killing the app process during authorization and returning from the external browser. Verify optional sync/revocation/reconnect on disposable accounts and data. Test haptics on/off and real chooser recipients/cancellation for both PNG and JSON.
5. Transfer disposable data PWA → APK → PWA via backup and via live Dropbox, verifying no silent content loss. Force process termination during saves/transfers and low-storage failure on disposable data. Capture evidence without credentials or personal content.
6. Optional instrumentation: `gradlew.bat connectedDebugAndroidTest` (or `./gradlew` on POSIX). The included test checks installed package/intent routing; it does not replace the WebView/OAuth/upgrade drills.

Record outcomes in [Phase 6 verification](phase-6-verification.md). Physical install, same-key upgrade/data preservation, hardware haptics, actual share destinations and live Dropbox are separate gates. Mandatory Phase 7 owner corrections/parity acceptance remains before Phase 8 release.
