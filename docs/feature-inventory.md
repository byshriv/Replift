## Persisted baseline shape

Root `replift.v1`: `ex`, `prog`, `wk`, `draft`, `pin`, `fav`, `have`, `st`, `lay`, `ms`, `cm`, `ph`, `pf`, `ob`, `wt`, `bk`, `pl`, and legacy version flags (`v2/v3`, settings migration flags). Preserve unknown fields during staged future migration.

- Exercise `{id,n,m,s,e,t,img}`. Routine `{id,n,day,ex,vals}` inside program `{id,n,routines}`.
- Workout `{id,t,r,title,dur,notes,diff,items}`; item `{ex,sets}`; set `{kg,reps,k,rpe,pr,est,done}`; draft has similar identity/title/items. `kg` and `reps` carry different quantities per logging type; incomplete inputs can be empty strings.
- Measurements keyed by name contain timestamp/value entries; custom measure names in `cm`; photos `{id,t,img}` use embedded JPEG data URLs. No stable IDs for every measurement/set instance yet.
- Profile includes name/gender/goals/experience/days/used/weight; onboarding holds step/mode/completion; layouts contain block IDs; estimate log `pl` capped at 200 in source.
- `st` mixes preferences, migrations and Dropbox credentials/status. `replift.dbx.base.v1` stores merge base/revision; `replift.dbx.oauth` stores pending PKCE state/verifier/key/redirect; install-dismiss key is in sessionStorage. These connection values are never fixture material.
